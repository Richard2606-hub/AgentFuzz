Fuzz a guard in your browser

Runs the real fuzzer in a Web Worker: the compiled guard wasm is executed by nearsim (NEAR's host ABI, accounts, keys, receipts and callbacks), attacked with property-based sequences, checked against INV-1..6, and every break is shrunk to a minimal repro. Same seed, same result as agentfuzz fuzz.

Audited as agentfuzz-guard-v1: the agent key may call only pay, so a wider key scope (like the naive builds' rotate_key) is reported under INV-3.

Prompt injection against the reference agent

Each corpus scenario is fed to the reference agent, which holds only a function-call key scoped to the guard. The compromised planner models a fully successful injection: it performs the legitimate work and every attacker instruction, so the guard is the last line of defence. The tool calls and transactions below are what actually executed on a fresh nearsim chain.

Your own injection, with a live model

Write a poisoned document and let a real model on NEAR AI Cloud plan the agent's actions; the guard then executes them on a fresh chain. Your API key stays in this page's memory: it is never stored and is sent only to cloud-api.near.ai, directly from your browser. Without a key there is nothing honest to show for custom text, because the compromised planner only replays scripted attacker calls.

Before your agent trusts a wallet, check its guard

Agents that pay or delegate budgets to other agents need to know the wallet guard on the other side holds up. Every NEAR account exposes the SHA-256 of the contract it runs (its code hash), and the AgentFuzz scoreboard on testnet records an audit for each guard build it tested: invariants held and broken, prompt-injection breaches, and the report hash anyone can re-run. This tab reads both straight from testnet, from your browser.

scoreboard.agentfuzz-28213.testnet

From an agent or CI

# exit code: 0 clean · 2 broken · 3 not audited · 4 no contract · 5 incomplete
node bin/agentfuzz.mjs check guard-reference.agentfuzz-28213.testnet

An audit is a claim by its submitter; it names a report that agentfuzz verify re-runs to the same hash. Pass --trust account.testnet to count only submitters you trust.

Simulate before you sign

Runs a transaction on a copy of mainnet or testnet before anyone signs it: the receiver's real contract code executes in nearsim (in your browser) on the network's current state, loaded on demand from public RPCs. You see what would really happen (NEAR and tokens in and out, keys added or removed, failures and fees), and what to worry about. Nothing is signed or sent; no wallet needed.

Try:

From the command line

# exit code: 0 nothing risky · 2 danger · 3 review (fails, refused, or not fully simulated)
node bin/agentfuzz.mjs simulate --signer you.near --to wrap.near --call near_deposit --deposit 1
node bin/agentfuzz.mjs simulate --tx tx.json --signer you.near

Limits: nearsim meters host calls, not every wasm instruction, so a call that would run out of gas on-chain can succeed here. Public RPCs refuse to serve the storage of contracts over 50 kB (wrap.near, USDt, Ref…); for those the page reads storage key by key from rpc.intea.rs, which is slower, and when it does not answer, the result is decoded from the transaction's arguments instead of executed, and says so.

Is this NEAR account safe?

For any NEAR account, yours or one you are about to pay: who can move its money (its access keys and what each may do), what code runs on it and whether AgentFuzz audited that exact build, and whether its name imitates a well-known account. Read straight from a public NEAR RPC in your browser; nothing to sign or connect, no wallet needed.

From the command line

# exit code: 0 nothing risky · 2 danger · 3 review · 4 account does not exist
node bin/agentfuzz.mjs scan you.near

What it can't see: whether a full-access key is yours (only you know), or what an app does with the key you gave it. A clean scan means no known risk pattern was found, not that an account is trustworthy.

Privacy & security

This page is static files on GitHub Pages. It sets no cookies, uses no browser storage, and loads no analytics or third-party scripts. On load it contacts only this site. When you press a button, it may contact the hosts below and nothing else: a Content-Security-Policy makes your browser block every other destination, for the page and for its Web Worker. Tools that read the chain never ask for keys and never sign or send anything.
